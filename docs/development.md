# Installation from Source

WeTTY can be installed from source or from npm.

To install from source run:

```bash
$ git clone https://github.com/butlerx/wetty.git
$ cd wetty
$ pnpm install
$ pnpm build
```

## Development Env

To run WeTTY in dev mode you can run `pnpm dev`.

WeTTY will then be served from `http://localhost:3000` on your machine.

The server will be using the [`conf/config.json5`](../conf/config.json5) config
file and be pointing at `localhost` on port `22`.

The sample config explicitly allows `http://localhost:3000`. Update
`server.allowedOrigins` if you access the development server through another
hostname or port. Production deployments must configure their browser-facing
origins explicitly; the listen address and request Host are not trusted.

The Dev server will rebuild WeTTY when ever a file is edited and restart the
server with the new build. Any current ssh session in WeTTY will be killed and
the user logged out.

## Browser SSH key management (Milestone 1)

The temporary **Create / show SSH key** button appears in the top-right corner
in both normal and development builds, including when disconnected. Open the
browser developer console, click the button, and copy the printed `ssh-rsa ...`
line into the remote account's `~/.ssh/authorized_keys`. Repeated clicks show
the same persisted key. Only the public key is printed; the private key stays in
IndexedDB and remains non-extractable.

To log in with the enrolled key, enable
[browser-key mode](browser-key-login.md). The button currently shares the
diagnostic's temporary storage scope; it is not an authenticated account key
selector.

Alternatively, in development mode, open the browser developer console and run:

```js
await window.wettyKeyDiagnostics();
```

This opt-in diagnostic creates or reloads a 3072-bit RSA key in IndexedDB under
`development-diagnostic-v1`. It reports key existence, non-extractability of the
private key, successful OpenSSH public-key export, and signing/local
verification. Only status and the public key are logged. Reload or restart the
browser and run it again: the public key should remain identical. Production
pages do not load `dev.js` and do not register this diagnostic. Use HTTPS or a
trustworthy localhost origin with WebCrypto and IndexedDB available.

The browser API in `src/client/wetty/auth/keys.ts` is:

```ts
const key = await loadSshKey(scope);
const publicKey = await key.publicKey(); // ssh-rsa <base64 SSH public blob>
const signature = await key.sign(data); // original Uint8Array, not a digest
const valid = await key.verify(data, signature);
```

The caller must choose an explicit storage scope. Future authentication code
must supply a stable deployment/tenant/subject scope; the diagnostic scope is
only for local development. Scoping is not authorization. No key is
automatically generated by the terminal, unless browser-key mode requests it. In
that mode only the public key and SSH authentication signatures are sent to the
backend.

The key uses WebCrypto RSASSA-PKCS1-v1_5 with SHA-256, exponent 65537, and a
non-extractable private CryptoKey. IndexedDB stores CryptoKeys by structured
clone; only the public key is exported. `sign` returns raw modulus-width
signature bytes, without SSH-agent framing. It hashes the original bytes
internally. The `ssh-rsa` public-key encoding does not imply SHA-1 signing. See
the [WebCrypto specification](https://www.w3.org/TR/webcrypto/) and
[IndexedDB specification](https://www.w3.org/TR/IndexedDB/).

Concurrent initializers adopt the committed key rather than overwriting it.
Storage failures or invalid stored keys reject the operation without an
in-memory fallback or silent replacement. Clearing the `wetty-ssh-keys`
database/browser profile loses the key; there is no private-key export or
recovery. Non-extractable does not imply hardware-backed storage or prevent
same-origin code from signing.

Automated tests use real Node WebCrypto and fake-indexeddb structured cloning.
They do not substitute for testing persistence after a full Edge restart on the
target OS; use the diagnostic above for that check.
